# Day 4 — Core Routes II: Write Operations & Business Logic

During the first three days of Week 6, I initially worked on the Event Booking System to apply the Sprint 1 requirements. On Day 4, I decided to continue the implementation using my **Cardiac Patient Monitoring System**, so I reapplied the previous requirements to this project and continued building its core functionality. The main focus of Day 4 was implementing the **Appointments** feature and its business logic using the service layer. I implemented creating, retrieving, updating, and deleting appointments, with separate access rules for Admin and Patient users. The appointment service verifies that the patient exists before creating an appointment and ensures that patients can access only their own appointments. I also implemented the required database transaction handling for operations that need atomic execution, with rollback in case of failure. The API uses DTOs for requests and responses, Entity Framework Core for database operations, JWT authentication, and role-based authorization. By the end of the day, the Cardiac Patient Monitoring System had the required appointment write operations and business logic implemented and was ready to continue with the remaining Sprint 1 work.
