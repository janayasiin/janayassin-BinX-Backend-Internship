# Day 1 — Sprint 3 Planning & N+1 Diagnosis

## Overview

Day 1 focused on establishing the Sprint 3 performance baseline and identifying unnecessary database queries in the Cardiac Patient Monitoring System.

The main focus was diagnosing **N+1 query problems** using EF Core query logging before applying any optimization.

---

## Sprint 3 Goal

> **Improve the performance of frequently used patient-data endpoints by identifying unnecessary database queries and establishing measurable query-count baselines.**

### Performance Target

> **Reduce unnecessary database round-trips in at least one identified endpoint and establish a measurable before/after query baseline.**

---

## 1. EF Core Query Logging

EF Core SQL logging was enabled in the development environment to inspect the SQL queries generated by Entity Framework Core.

Sensitive data logging was enabled only in Development for debugging purposes.

## 3. Identifying a Genuine N+1 Problem

A dedicated performance endpoint was tested:

`GET /api/Patients/performance/n-plus-one`

The test environment contained **58 patient records**.

The EF Core logs showed that:

1. One query retrieved the patients.
2. A separate medication query was executed for each patient.
3. The same query structure was repeated with different `PatientId` values.

This resulted in:

**1 + 58 = 59 database queries**

![N+1 Queries](./screenshots/n-plus-one-queries.png)

---

## 4. Performance Baseline

The N+1 endpoint was measured before applying any optimization.

| Metric             | Baseline |
| ------------------ | -------: |
| Patients processed |       58 |
| Database queries   |       59 |
| Response time      |   285 ms |
| N+1 detected       |      Yes |

The response timing was recorded by the custom `RequestTimingMiddleware`.

This baseline will be used in Day 2 to measure the effect of query optimization.

---

## 5. Sprint 3 Backlog Task

### Optimize Patient Medication Loading

**Problem:**
The `/api/Patients/performance/n-plus-one` endpoint executes multiple database queries when loading medications for patients.

**Current Baseline:**

* 58 patients
* 59 database queries
* 285 ms response time

**Target:**
Reduce unnecessary database round-trips by using an efficient EF Core loading strategy such as projection or eager loading.

**Priority:** High

**Planned:** Day 2 — Query Optimization
